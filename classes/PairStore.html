    Class PairStore

    Everything pairing keeps on disk, under <state>/pair.

    Files rather than one database because two processes touch it: serve holds the socket and writes the link state and command results, and the CLI writes the pairing record and the operator's decisions. Each file has one writer, which is what keeps the two from overwriting each other. A decision is its own file for the same reason: pair approve never rewrites a command record that serve may be updating.

      Replaces the whole id map in one write, for the pairing that is still on disk.

      A frame that was refused never reaches here, so a refusal leaves the old map untouched. A record for another node, or none, is left alone, so a frame that outlived an unpair cannot bring a pairing back.
